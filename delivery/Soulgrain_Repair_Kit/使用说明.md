# 可复现真实修复补丁（可选，不是查看工程的必需步骤）

正常查看请直接下载 A、B、C 的 REVIEW.blend。这个小补丁包适合需要在 Mac 本地重新生成**包含完整源归档场景**的三个大工程时使用；不依赖 Codex，不需要安装第三方库，也不访问网络。

**结果不是全鞋最终验收版。B 上部内衬、鞋眼邻近外壳和包边仍待修；C 深折层与收口仍有明确未建区域。不要把检查工程用于正式替换网站资产。**

## Mac 操作

1. 将整个 ZIP 隔空投送给 Mac，双击解压，保留文件夹内的目录结构。
2. 从原始 `soul-semantic-v22-final-01` Release 下载 `SOUL.NEW.blend`。只接受 SHA-256 为 `725756904a0c71ee9c927b3e39332655c4cd175d3b9d55d0272ae70adb105183` 的原件，不接受别的标注版本。
3. 先保存自己尚未保存的其它工作。重启 Blender；不要运行旧 V2.2 分解/自动标注脚本。
4. Blender “文件 → 打开”，打开原始 `SOUL.NEW.blend`。不要更改原件。
5. 点击顶部 “Scripting / 脚本”，在 Text Editor（文本编辑器）使用“打开”，选择本包 `生成三个修复工程.py`，点击“运行脚本”（三角形）。
6. 回到三维视图，鼠标放在模型上按 N，打开右边的 **Soulgrain 修复** 页签。
7. 点击“生成 A、B、C 独立工程”，在文件窗口再选一次刚打开的原始 `SOUL.NEW.blend`。
8. 等待完成。工具会检查源文件、当前内存中的几何/UV/标签、对象变换和原始材质，防止悄悄丢弃未保存修改。随后在补丁包旁建立一个新的 `RESULTS_日期时间` 文件夹，生成三个 `.blend`。过程中界面会短暂忙碌。

每个完整工程有 `SOURCE_UNCHANGED__ORIGINAL_LABELS` 源归档场景与 `REPAIR_A/B/C__REAL_GEOMETRY` 修复场景，可从右上 Scene（场景）菜单切换。生成结果需约 0.5 GB 磁盘空间。输入文件会另拷贝到补丁包的 inputs，不会覆盖用户原件。

输出目录已有同名结果时工具拒绝覆盖。任何校验失败都应先保留工作、阅读错误；不要通过删除校验代码强行应用。

## 检查新增结构

右上 Outliner（大纲）搜索 `REPAIR_` 可以找到本轮真正的新网格。对象名称及 `repair_is_new` 属性用于区分新增几何和原始面。`WORK_` 是保留原面 ID 的派生旧网格。

源归档、原 JSON、原 UV/PBR 和原人工标注保留。新面使用独立施工 UV；不冒充原图集已经无缝。真实拓扑已变化，不要将原语义 JSON 覆盖导入修复场景，也不要在修复场景运行旧自动分类。

## 测试与限制

在 Linux Blender 5.2.2 LTS 中已通过真实源文件重放 A→B→C，源/剩余旧面的逐面几何、UV、标签和材料校验通过。Mac Blender 5.2.3 尚未实机验证。界面预检若遇到跨版本资源校验不符会停止，而不会略过保护。

补丁里的 source_reader.py 仅作为只读数据校验库导入，不注册旧语义工具。所有新增补片都是来自实际施工数据的可编辑网格，不是显示代理或替代鞋模。

新增补片的未引用顶点已清理，清理前三角面空间坐标与最终面完全一致。此步骤不处理任何原始顶点或原面 ID。
