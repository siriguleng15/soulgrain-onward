# 修复层、保护机制和后续路线

## 源模型与新几何是两个版本域

- `_sgo_v1_meta`：V2.2 原工作文件元数据。V3 将它原样冻结，不改旧哈希来容纳新拓扑。
- `_sgo_repair_studio_v3`：新的独立修复层注册表，schema=`soulgrain.repair-layers/3.0`。
- `source_file_sha256`：创建工作副本时读取的输入工程 SHA-256。
- `sources`：每个源对象的坐标、边、面、UV、材质索引、变换、父级、持久化法线、语义及源面 ID 指纹；另记录修改器、约束和 Shape Key 状态。
- `resources`：源材质节点、连接、图像、颜色空间和内嵌图像字节签名。
- `tasks[UUID]`：目标稳定 part UUID、分类 ID、真实源对象/面/顶点/边引用、轮廓 UUID、算法及参数、候选版本、用户编辑和确认记录。

范围副本 SELECTOR、引导 GUIDE、候选 PREVIEW、确认 ACCEPTED 和撤回 RETRACTED 都有独立对象 UUID 和任务归属。只有注册的修复对象可绕开旧版“额外 Mesh”误报；复制出来但未登记的陌生 Mesh 仍拒绝。修复对象不会冒用源 `_sgo_object_id`。

新增确认面使用 `sr3_geometry_epoch + sr3_object_uuid + sr3_face_id`，来源 `NEW_REPAIR_NOT_ORIGINAL_HUMAN`。`sr3_face_id` 只在这个补片 epoch 内有效。原源面 ID 从不拿来标记新面。未来重新拓扑必须创建新的几何 epoch、显式迁移；不以改旧哈希伪装无变化。

## 状态流转

`SCOPE → BOUNDARY → PREVIEW → ACCEPTED → RETRACTED / DELETED`

未经明确点击确认的 PREVIEW 不能进入正式导出。用户在预览中原生拖点、删错面和加密不会自动重建整块候选。重新生成会创建新的 variant，旧 variant 保留。

确认前重新核验源模型，检查接合边覆盖、固定点位移、退化、重复、非流形边、自交、参考法线、与已确认源面的交叉和共面面积覆盖。补片间也检查碰撞。与未确认参考（含 UNKNOWN/AUTO/既有待验收修复）的冲突需要独立明确复核，绝不自动删除或改类这些参考。

确认后保存初始和最终控制点、实际最终面数/位置、算法参数、用户编辑与法线/UV/质量记录；确认几何、UV、变换、材质绑定和新增稳定面 ID 再被改动时阻止正式导出。

## 边界与选择

边界引用是原源对象 UUID + 两端原顶点 ID，并带独立轮廓 UUID；面引用另带原源面 ID。不是仅靠当前面序号或坐标猜身份。

为跨 UV 重复顶点读取连续轮廓，分析时允许完全相同坐标的虚拟等价节点；不会焊接源顶点。生成补面采用两条轮廓所有弧长断点的并集，保留源折线拐点，不把不等距源边界重采样成穿进原表面的直线。包头提案明确记录为顶点约束引导，不伪称真实物理边界。

范围副本的几何、面连接、变换和来源属性也做校验。其临时平滑显示标志不参与几何身份；源网格的持久化法线仍受完整保护。

边界锁定只约束新预览点，不修改源。预览端点合并仅发生在本次生成的新几何内；锁定边界和独立补片仍不是把它焊进原鞋。正式焊接、删退源错误面或跨 UNKNOWN 的切割需要后续单独授权。

## 有界计算

- 范围副本上限：120,000 个已标注面，超过后须选更细子部件。
- 边界上限：512 条边；双轮廓断点并集最多 512 点。
- 生成上限：20,000 面、25,000 点；曲面横向段数 2–32。
- 质量检查：最多 40,000 局部三角面、50,000 个邻域参考三角面。
- 参考数组缓存上限：256 MiB，按源对象几何版本复用。该限值不代表 Blender 整个进程只占 256 MiB。
- 相交候选逐批流式处理，不构造无界的全模型碰撞对列表；单次候选遍历最多 100,000 对，交叉检查预算 8 秒。超限只报告未完成并拒绝确认，不假装检测通过。
- 短计算目前同步执行；尚无完整长任务进度/随时取消的模态界面。缩小范围可避免长计算。正式导出用同一 Blender 可执行文件在隔离临时副本中完成，有 90 秒子进程上限；不用额外安装软件。

诊断不等于工业 CAD 的精确实体求交：浮点容差、近共面和非常细长面仍需用户观察。退化/自交检测不证明整鞋已经水密，正常开孔必须由用户确认。

## 保存、正式导出与回退

保存工作台可保留未确认候选。正式导出仅包含源对象与 ACCEPTED 补片，并保留其来源元数据和源 PBR/语义档案。工具先另存私有临时副本，在独立 Blender 子进程删除该临时副本中的范围/引导/未确认对象，保存到全新输出名，再重开验证坐标、UV、语义、ID、变换与 PBR。这些删除不发生在用户工作台，更不发生在原始文件。

Linux 5.2.2 的 `bpy.data.libraries.write(Scene)` 在真实文件测试中出现过崩溃，因此没有交付该导出路线；现用隔离副本写出并回读的路线已经测试。

V3 不允许重新标注源面。若发现源标签应纠正，返回保留的语义工作文件，经过人工确认后另建源版本；不要在修复阶段偷偷重识别 UNKNOWN。

## 分阶段后续

1. **本次交付**：真实鞋底缺角、原生预览纠错、边界约束、检查/确认/撤回、隔离导出；包头桥接提案可操作但当前冲突待用户调整。
2. **Mac 验收**：检查侧栏、原生选择/拖点、撤销重做、隔空投送、文件保存与子进程导出；先确认工具交互，再扩展施工范围。
3. **包头边界完善**：用户指定真正需要新侧壁的上下轮廓，排除现有正确表面覆盖；仍不删除 UNKNOWN。
4. **鞋身双层**：只针对确认过的外层/脚底连接边规划内衬，加入局部厚度、足部空间与自交约束；不对整鞋 Solidify。
5. **翻筒与四层检查**：局部剖切、间隙约束、折线连续关系，保护外层造型；不假设处处有四张独立皮。
6. **纹理与最终结构**：对已验收新几何单独建立 UV、转移原纹样、记录不确定区域；最后才讨论正式连接、焊接、可拆分零件与 GLB 输出。

本次未修改网站、动画、正式模型或旧插件，未合并主分支或部署。
