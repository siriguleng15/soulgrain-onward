# A/B/C 语义兼容故障与迁移

## 根因

此前施工工程的活动场景没有 `_sgo_v1_meta`，工作对象的 `_sgo_object_id` 也被移除，只留下 `repair_source_object_id`。下载版省去了原始场景，因此旧插件连原始语义入口都找不到。新增补片没有完整面级语义字段。这是交付工程的兼容缺口，不是用户操作错误。

大部分旧面上的 `sgo_part/status/confidence/issue` 和 `sgo_source_face` 实际仍在。施工删除过部分已确认面后，源面 ID 有间断；旧插件把源 ID 必须等于当前面序号作为校验条件，即使简单复制旧元数据，也会因拓扑变化继续失败。不能用旧面索引强行套用。

完整施工 `.blend` 还保留一份原始场景；供下载的 REVIEW 文件没有。两者活动修复场景的逐面数据核验结果相同。

## 只读盘点（活动修复场景）

| 工程 | 保留的原面 | 其中 HUMAN | 原 UNKNOWN | 新增、原先无完整语义的面 | 已退出当前几何的原面 | 其中原 HUMAN |
|---|---:|---:|---:|---:|---:|---:|
| A | 1,450,162 | 332,811 | 412,512 | 25,240 | 48,877 | 25,449 |
| B | 1,351,337 | 233,986 | 412,512 | 44,848 | 147,702 | 124,274 |
| C | 1,281,758 | 164,407 | 412,512 | 79,892 | 217,281 | 193,853 |

原始 SOUL 为 1,499,039 三角面、358,260 HUMAN 面。全部 412,512 个 UNKNOWN 原面仍在，标签没有被自动识别、归类或删除。

“已退出当前几何”指上一轮施工记录中从工作网格替换/移除的原面，不是本次迁移删除。193,853 个已退出 C 几何的原 HUMAN 记录不能凭空贴到新补片上。原始工程和完整源标签档案保留这部分历史；新检查文件内嵌原 JSON、全部原标签及逐任务退出清单，便于溯源。标签档案不包含被移除面的完整网格；回退几何仍使用保留的原始 SOUL 或阶段工程。

## 实际迁移流程

1. 以原对象 UUID + 原 `sgo_source_face` 建立精确查找表。
2. 对 C 每个保留面核对三角形三个角点坐标、UV、材质面索引、P/S/C/I 四项语义和对象世界变换。不是最近点配准，也不靠包围盒。
3. 核对当前源 ID 的缺失集合与 A/B/C 已保存施工记录逐一相等，禁止额外丢面。
4. 七个新增对象的全部顶点和面与对应施工 payload 逐项相等。新增归属依据为具体施工任务及生成区域，不是重新识别 UNKNOWN。
5. 为新拓扑建立新的资产版本、对象 UUID、当前稳定面 ID 与来源哈希。源面 ID 原值不变；新增面源 ID 为 -1。
6. 写入新的元数据和不可变源标签镜像，并保存到新的 C 检查文件。其几何、UV、PBR 和变换相对 C REVIEW 不变。

## 新增面明确不是原 HUMAN

新增 79,892 面初始状态为 `3 / REPAIR_PENDING`，自动置信值为 0。分配到鞋底、鞋身内衬、翻筒内面等任务分类，只表示施工归属，等待用户验收。新增面属性记录 origin=NEW、A/B/C 任务和施工 payload 面行号。显式验收后可以记当前 HUMAN，但来源永远仍为 NEW，原源面 ID 永远仍为 -1。

旧 HUMAN 在保留面上逐位继承，不需要重新标注。原 UNKNOWN 冻结；本检查版禁用自动识别与扩展重分类。不能把一个未识别源面自动当作修复正确的表面。

## 插件校验没有关闭

V2.3 按当前修复 epoch 严格校验顶点、拓扑、UV、材质面索引、变换、持久化法线设置、源面映射、原标签镜像及原 PBR/图像资源。源 ID 有间断是合法来源映射，但不能改变。当前面 ID、原源面 ID 和局部数组索引分开记录。

Blender 的运行时 corner-normal 缓存跨平台/版本不稳定，不用于资产身份；改用真实保存的 custom normal、平滑和锐边设置。Blender 模式切换可能删去全 false 的 sharp 标志层，规范化为“缺省与全 false 等价”；非零锐边变化仍拒绝。没有放过几何、UV 或面序变化。

新 JSON 包含 epoch、精确来源数组、版本哈希和独立 float32 置信度；不再由旧分段格式的四位小数舍入改变数值。导入前整包验证，原 HUMAN 批量导入保护，旧原模型 JSON 不能导入 C 新拓扑。

## 如何继续检查 C

使用 V3 插件或单独 V2.3 插件（二选一），打开 `Soulgrain_C_SEMANTIC_V2_3_CHECK.blend`。读取零件管理器后可隐藏、单独查看、选中、切换原 PBR 和语义颜色，以及进入动态分解工作台。新增待验收面有独立显示开关。这个工程保留原 C 的结构问题；“兼容校验通过”不代表此前局部修复已经全部验收。

若要在 C 上新施工，点“另存并建立 V3 只读源工作台”，建立第三份新文件，不覆盖 C 检查工程。V3 会冻结当前 C 几何及其标签，再在新层补面。
