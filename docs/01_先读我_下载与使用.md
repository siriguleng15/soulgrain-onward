# Soulgrain Repair Studio V3.0 — 鞋底修补 MVP

这是可运行的 Blender 插件与真实 SOUL 演示工程，不是全鞋自动修复器。本次另附 C 阶段语义兼容检查工程，解决上一轮工程无法被零件管理器识别的问题。

## 文件怎么选

| 文件 | 用途 |
|---|---|
| `soulgrain_repair_studio_v3.py` | 推荐使用的完整单文件插件，包含 V2.3 修复工程兼容层和 V3 工作台；不依赖另外安装旧插件 |
| `Soulgrain_REPAIR_STUDIO_V3_DEMO.blend` | 从真实 SOUL.NEW 创建的独立工程；原始 1,499,039 个三角面和语义冻结，提供后跟与包头两个**未确认**补面预览 |
| `Soulgrain_C_SEMANTIC_V2_3_CHECK.blend` | 既有 C 阶段几何的语义兼容副本；可通过零件管理器、颜色和动态分解检查；**不是再次完成几何修复的新版成品** |
| `soulgrain_semantic_v2_3_repair.py` | 只需要验收 C 时可使用的兼容插件；与 V3 二选一，不同时启用 |
| `Soulgrain_C_V2_3.semantics.json` | C 的新拓扑版本语义导出；不能拿它覆盖原始 SOUL 的 JSON |
| `Soulgrain_工具教程与验证.zip` | 脚本、教程、审计、真实测试及对比图；两个大型 .blend 单独下载 |

下载后先把文件通过隔空投送传到 Mac，在 Finder 新建文件夹保存。两个原始文件及既有 V1/V2 工作工程不要移动、重命名或覆盖。

## 在 Mac 启用

实际自动测试环境：Linux Blender **5.2.2 LTS**。目标 API 为 Blender 5.2.x；你的 Mac **5.2.3** 尚需本机交互验收。无需安装 Codex，不需要 pip 或第三方 Python 库。

1. 在旧插件列表里取消勾选 Soulgrain Semantic V2.2 等旧插件。文件保留；不要同时启用两个 Soulgrain 版本。
2. 打开 Blender。通过“文件 → 打开”打开演示 `.blend`，不要打开原始工程直接施工。
3. 顶部切到“Scripting / 脚本”。在文本编辑器点“打开”，选择 `soulgrain_repair_studio_v3.py`，点“运行脚本”（三角形按钮，或把鼠标放文本编辑器按 Option+P）。
4. 回到“Layout / 布局”。把鼠标放三维视图，按 N 展开右侧栏，点“Soulgrain”。展开“几何修复工作台 · V3.0 MVP”。
5. 若想每次启动都启用，可在“编辑 → 偏好设置 → 插件”的菜单使用“从磁盘安装”，安装此 `.py` 并启用。初次用上面的“打开文本 → 运行”即可；重开 Blender 后需再次运行，直到你完成插件安装。

插件不会自动执行嵌入脚本。不要为了本工具开启所有文件的自动执行。

## 先试后跟演示（不碰原鞋）

1. 在“已有修复任务”中选择鞋底的后跟任务（名称后有任务短 ID）。橙色是新增预览，原鞋仍在原位。源对象默认不可选。
2. 点“调整预览”。进入的是橙色补片，不是原模型。左键点内部点，按 G 拖动，左键确定；Esc 取消当前拖动。滚轮或触控板缩放、中键拖动旋转；没有鼠标可在偏好设置启用模拟三键鼠标。
3. “切换边界锁定”控制新补片的接合点。锁定时边界点自动取消选择并恢复约束位置，内部点可以编辑。解锁只用于纠错；确认前仍要通过接合检查。
4. 用 Blender 原生框选 B、套索、圈选 C 调整选区。“仅平滑选中的内部控制点”与“仅加密选中的内部边”只修改预览局部。原生删除菜单可以删预览错面；删坏边界会被质量检查拦截。
5. 可反复修改，不必重新生成。若点击“生成新候选”，旧手改候选仍保留，可用“切换到上一个候选”返回。
6. 点“检查源保护、穿插、边界及 UV”。演示后跟只覆盖一个可靠的小子区，不代表整个后跟缺口已经自动修完。本次最终检测未发现该小补片与已确认源表面的穿插；若你调整后发现未确认参考冲突，必须单独观察和复核。
7. **看清预览再勾选**边界意图、UV 待处理许可、必要的参考冲突复核及“我确认”。点“确认本次修复”会再次核验，才把它变成独立的真实补面对象。
8. “撤销本次补片”仅撤回/隐藏当前独立层。“撤回后重新编辑预览”可重新调整，之后必须再次检查和确认；“删除本任务补片”只删该补片。源面不会被删。原生编辑撤销用“编辑 → 撤销”；图形界面的撤销/重做需在你的 Mac 再验收。
9. “导出已确认修复版工程”写到**新的** `.blend`，只含源模型与已确认补片。不含引导线、范围副本或未确认候选。新面尚未转移纹理时仍明确保留 UV 待处理记录。
10. 若要保留未确认的手改进度，使用“另存整个工作台”，起一个新名字。不要覆盖原始 SOUL、V2 或以前工作副本。

演示工程没有替你点击确认。自动测试中的确认仅在另一个测试副本执行，不影响下载工程。

## 自己圈定一个鞋底缺角

1. 打开语义工程，运行插件，点“另存并建立 V3 只读源工作台”，选择全新文件名。
2. 待修部件选鞋底或其已标注子分类。默认只使用 HUMAN 区域；UNKNOWN 不能作为目标。AUTO/既有修复待验收区域只有在明确勾选后才能作为约束参考。
3. 点“指定局部范围”。出现带真实源面/源顶点映射的线框范围副本。它不是正式修复模型。通过原生边选择选一条缺角开链，或在面选择模式框选边缘旁的面。
4. 点“检测所选边界”。若有分叉、多层、超过 512 边或无法成链，会拒绝；缩小选区，不能强行封鞋口、鞋眼或语义截边。
5. 开链选“源开链 + 目标引导”，点“创建 / 编辑目标引导”，拖动引导控制点。两端必须接回源边界。高度、弧度均是**模型原单位**，不是毫米。
6. 点“生成新候选”，按上面的流程手改、检查和确认。

“闭环小洞”要求一条明确闭环；“双开链桥接”要求两条用户指定开链。仅有标签边界不表示真实缺口。

## 包头第二案例

演示的双轮廓来自真实 HUMAN 包头顶点约束，是可编辑的桥接提案，不是已经核实的物理开口。当前提案与现有 HUMAN 表面相交，检查会失败、确认会被阻止；请调整边界或提供真正缺损的两条轮廓。

本版不会为让桥接通过而删除原包头、隐藏冲突源面、把 UNKNOWN 改类或用简单替代模型冒充原鞋。端部三角面和内部四边面都是真实新增网格。

## 当前边界

本版实现小洞、开链轮廓延伸和双开链桥接；检测只针对指定范围、边界与候选，不是自动理解所有鞋类开口。复杂内衬生成、足部空间保护、四层交互剖切、纹样重新烘焙和全鞋修复尚未实现。

新补片有独立任务层管理，尚未加入旧版动态分解缓存；源语义组件及 C 既有修复的零件管理/分解仍可使用。独立补片不会自动焊接进源网格；本阶段是可回退的真实补面层，非最终一体水密鞋模。
