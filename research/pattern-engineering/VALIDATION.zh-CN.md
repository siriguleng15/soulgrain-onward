# 验证记录与适用范围

本记录区分“程序和坐标关系通过检查”与“实物鞋面已经还原”。本轮前者有可复算证据，后者仍需工厂和实物补充资料；不能将两者互换。

## 1. 原图、标定与轮廓

| 检查 | 当前结果 | 能说明什么／不能说明什么 |
|---|---|---|
| 原图溯源 | 12 张原始字节保留，尺寸和 SHA-256 写入 manifest | 可核对来源；不是拍摄尺度证明 |
| 网格观察 | 471 点，377 拟合、94 留出 | 有独立留出交点检查，不是留出实物纸样测量 |
| 网格残差 | 拟合 RMS 0.391 mm；留出 RMS 0.390 mm；最大 1.479 mm | 只评价单应模型拟合网格的程度 |
| 校准外接框 | 268.684 × 257.139 mm | 基于标称 10 mm 垫板网格 |
| C 图标注差异 | 对 267 × 262 mm 为 +1.684、−4.861 mm | 差异保留，不以缩放掩盖 |
| 外轮廓 | 206 个不重复采样点，另有闭合点；完整不规则形状 | 简化容差是原像素单位，不等于毫米精度认证 |
| 结构信息 | 13 鞋眼、4 个用途未确定的内部标记、7 条人工读图参考线 | 线条功能及缝份仍须确认 |

`data/digitization-validation.json` 保存上述数值；`data/pattern-overlay.svg`、`calibration-source-overlay.jpg` 用于目视复核。单应矩阵像素往返的浮点误差很小，仅证明同一矩阵及逆矩阵相容，不证明纸张平整或绝对尺寸无误。代码中的审查带宽不应解释为经实验确定的测量不确定度。

尚未纳入：垫板实际格距、镜头径向畸变、纸样翘曲、拍摄地面不共面、裁断边遮挡及笔迹粗细的独立误差预算。

## 2. 真实裁片网格与可逆性

运行 `node scripts/pattern/check_mesh.mjs`，实际输入为 `public/pattern-engineering/data/pattern-mm.json`，输出 `data/mesh-validation.json`。合成凹多边形单元检查使用 `--unit-only`，两者不能混称。

当前真实网格有 **8,453 顶点／16,125 三角形**，最大边长不超过 4 mm。检查包含：

- 实际不规则裁片面积减去孔面积与三角网格面积一致；边共形、无孤立顶点、Euler 拓扑关系成立。
- 完整平面时边界回归误差为 0，主伸长为 1，无退化三角形。
- 平面、中间态、成形态共享完全相同的顶点身份及三角索引。
- 100 次完整折叠／展开后，源平面坐标及索引未改变；回平面数值漂移为 0。
- 300 个种子随机三角形／重心坐标完成双向定位，最大平面往返数值误差约 `8.53e−14 mm`。这只是映射算法浮点误差，不是实物定位精度。
- 孔中心保持无面料；解析参考点可随形变显示，但不能变成可安装的表面锚点。
- 人工照片约束可调整成形状态，仍保持准确回平面，并报告约束残差。

**E03、E12、E13 的原照片孔边轮廓自接触或断裂。** 计算网格对这三孔采用观测圆心／半径的 24 边近似，原始轮廓 JSON 与 SVG 未覆盖。该近似只解决计算拓扑，孔边尺寸和形状仍须实测。

## 3. 形变质量与照片拟合

界面默认使用 `PHOTO_DEFORMATION_HYPOTHESIS`，并非 `RecommendedDeformationParams()` 的通用示例。

| 项目 | 默认照片假设 | 通用示例 |
|---|---:|---:|
| 最小／最大离散主伸长 | 0.971405 / 1.031610 | 0.906775 / 1.120358 |
| 最大离散主应变绝对值 | 约 3.16% | 约 12.04% |
| 成形态退化三角形 | 0 | 0 |
| 完整展开误差 | 0 | 0 |

默认假设的 21 个进度状态均为有限坐标。小于 5% 的检查阈值只是当前数值诊断界限，**不是布料材料标准或可生产标准**。改变翻折带、包覆和人工约束后必须重新检查；不能沿用默认数字。

照片拟合使用 12 个人工假设的鞋眼对应点，E06 排除。RMS **10.578 px**，最大 **21.573 px**，属于同一组拟合点的样本内残差。没有独立保留照片，也没有证明鞋眼身份一一对应；不能称为外部精度验证。完整侧轮廓和底部绷帮连接边仍未拟合。

`node scripts/pattern/check_photo_fit.mjs` 验证照片显示坐标转换、100 个真实网格点的投影与回平面映射、无命中返回空值、扣件按层投影以及拟合残差披露。**基础网格更新后必须重新运行**，因为三角形编号依赖实际网格。输出为 `data/photo-fit-validation.json`。

没有执行：真实布料本构、针脚／缝合求解、绷帮求解、层接触、三角自交及物理碰撞。翻下的翻筒会导致侧投影方向反转；这不是三维网格翻面的充分证据，也不能据此推断没有自交。

## 4. 扣件推导和反向定位

蓝色扣心语义已经用户确认，是第五段支撑完整圆的圆心。原图拟合蓝扣心仍作为默认位置，未为消除模板误差移动它。

`check_clasp_geometry.py` 从真实图片复算框架／模板；`check_clasp_geometry.mjs` 验证四分圆连续性、圆心与弧终点区别、正反模板变换、原观测位置保留和未确认裁切参数的输出阻断。

四个固定端与每颗扣心的鞋身／翻筒投影各有单独身份。单像素可能命中多个层，程序保留警告；无命中不强制找最近顶点。**布面扣心投影不是 PU 公母扣安装孔。** 本轮未对四合扣公母件及皮条重叠进行物理扣合验证，不能直接据此钻孔或裁切量产。

## 5. 浏览器与实机范围

自动检查及构建检查验证的只是指定环境中的功能。桌面 Chromium、带触控参数的浏览器或 iPad 分辨率模拟都不是 iPad Safari 实机测试。若交付包另有浏览器测试 JSON、截图和日志，应结合其实际浏览器版本、视口、触控输入、下载记录及 WebGL 环境阅读，不能仅凭截图推断性能。

本轮实际执行了 25 项 Chromium 功能检查，包含真实触控事件模拟、双视图点选、双指缩放、中断动画、工程文件恢复和错误源拒绝、SVG／JSON／CSV 实际下载，以及 2400／2560 px PNG 编码校验。没有浏览器未捕获异常或失败网络请求。证据见 `public/pattern-engineering/verification/browser-validation.json` 与同目录截图。

当前测试机使用 Linux 头部无界面 Chromium 与 SwiftShader 软件 WebGL，连续动画的实测帧率偏低。20 次几何更新 CPU 中位数约 3.1 ms，静置 RAF 约 16.7 ms；这些数字不能替代真实 GPU 或 iPad Safari 的整帧性能。未达到“已证实 iPad 流畅”的验收结论。

真实 iPad Safari 仍需检查：首屏载入、双指缩放和单指旋转／平移、轻点与拖动区分、反复折叠中断、照片叠加、PNG 下载、文件选择与工程恢复、后台返回及 WebGL 上下文恢复。本轮文档不声明这些实机检查已经完成。

## 6. 当前验收结论

可审核：数字化轮廓与原图叠加、真实网格、固定身份动画、双向坐标映射、用户扣件推导、条件式反向投影及风险明确的定位导出。

未通过实物验收：绝对纸样尺寸误差、隐藏结构、真实工序、完整成鞋侧面形态、PU 公母扣安装孔和量产公差。完成这些验证需要下一轮现场尺寸、折叠／缝合标记及实物定位样，不应以当前视觉近似替代。
