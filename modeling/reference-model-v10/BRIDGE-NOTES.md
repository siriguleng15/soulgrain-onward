# 实际模型与真实裁片的照片桥接

本模块保持两个独立的几何身份：真实裁片的三角形／重心坐标，以及修正 GLB 的对象／三角形／重心坐标。二者由同一张最终效果图上的像素连接。AI 网格的 UV、顶点编号或归一化长度都不会被当作真实裁片坐标。

当前上传文件本身没有 UV 或独立部件语义。新增面料标签依据可见形态和照片区域划分，用于保守限制投影；它不是已验证的工厂分层、缝合或物料清单。将来即使加入纹理 UV，也不能用图集替代真实裁片展开。

## 计算关系

既有裁片成形假设为 `F(q)`，纸样毫米点 `q` 对应照片像素：

```text
u = ox − sx·F(q).x
v = oy − sy·F(q).y
```

实际模型配准另行保存正交单位基 `r`、`up`、`f` 及显示尺度 `Sx,Sy`：

```text
u = Ox + Sx·dot(P,r)
v = Oy − Sy·dot(P,up)
rayOrigin = r·(u−Ox)/Sx + up·(Oy−v)/Sy − R·f
rayDirection = f
```

射线的第一个实际表面必须是明确标记且符合请求层的鞋身／翻筒面料。皮条、扣头、鞋眼、鞋带、鞋舌、鞋底、另一层面料及用途不明对象会遮挡其后方表面；程序不会穿透这些对象，把不可见的布面当成已观察安装面。某个像素命中多层时，保留层选择和多义性警告。没有命中时保持空值。

每个对应保存：原裁片三角形与权重、原裁片毫米坐标、源照片像素、实际 GLB 对象／图元／三角形与权重、模型坐标、模型文件与纸样数据的哈希，以及风险说明。实际对象路径和几何缓冲指纹用于拒绝其他版本的三角形编号；发布前使用实际 GLTFLoader 核对静态路径与指纹。模型坐标以 `model-unit` 标注；未经过独立尺量校准前不称为毫米。

重投影残差接近零，只证明同一个配准变换和射线计算数值自洽；它不能证明配准吻合实物、隐藏结构正确或固定点达到生产精度。

## 同身份裁片映射壳层

`build_bridge.py --shell` 可逐个投影原裁片顶点。原始毫米坐标、顶点 ID 和完整三角索引保持不变；每个成功命中的顶点另存实际模型三角形身份。无命中、超出照片或被遮挡的区域保留缺失掩码。绘制子集同时保存原始三角形编号，禁止把子集 `faceIndex` 直接当成原裁片编号。

壳层由有限密度纸样三角片插值，属于模型表面参考覆盖，不表示真实缝合求解。平面显示框架至壳层的连续插值只表达对应关系；显示框架依赖假设相机尺度，不能宣称材料等距或已还原工厂展开过程。

由 AI 生成的单一闭合表面未必含有皮条后方或翻筒下面独立的真实鞋身面料。因此，即使照片中能画出四个皮条固定端，也不能保证实际扫描式网格存在相应可安装布面。安装端点或扣心没有命中时，文件保留 `actual: null`；这不是需要用最近点补齐的显示缺陷，而是当前模型缺少工程结构证据。后续应补充真实分层鞋面、缝合和扣合数据，再重建对应。

报告可另外提供 `visibleClothExamples`：从已经完整命中的原纸样三角形内部取最多四个鞋身、四个翻筒取样，展示可见布面上的双重表面身份。它们明确标注“非扣件定位”，只证明当前数值桥接在这些可见面上工作，不是新增设计点，也不替换八个原安装参考点。

## 可复算检查

```bash
node modeling/reference-model-v10/check_bridge.mjs
python3 modeling/reference-model-v10/build_bridge.py --shell
node modeling/reference-model-v10/check_bridge.mjs --actual
```

第一条使用真实纸样和明确标注的独立双平面算法样例，检查分层、硬件排除、未知面不吸附、双重身份、失效模型身份拒绝及数值往返。它不是产品验收。第二条读取实际修正 GLB 与 `public/reference-model-v10/model-data.json` 的 `photoRegistration`，生成对应数据。第三条以实际 GLTFLoader 再核对对象路径、缓冲身份、锚点、遮挡结果与壳层复位，写入 `public/reference-model-v10/bridge-validation.json`；不能用样例检查结果替代实际模型验证。

当前实际数据覆盖 1,670／8,453 个原裁片顶点（19.8%），仅绘制 2,720／16,125 个完整命中三角形。原八个安装参考点均未获得布面对应；八个可见布面演示取样单独保存，绝不替代安装点。覆盖率只描述当前可见投影，不是已还原裁片或缝合工艺的比例。
